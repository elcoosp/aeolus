## 4. The allocation contract (v0.5 §3) — findings FIRST, then the fix

The contract test failed against the shipped v0.4 code — the report's
claims were wrong in two places:

```
$ cargo test -p aeolus-core --test alloc_contract
test diff_of_equal_plans_allocates_zero ... FAILED
  left: 3, right: 0
test cached_hit_allocations_are_bounded ... FAILED
  a warm hit clones the cached plan        <- the OPPOSITE finding: 0 allocs
```

1. **`diff()` allocated 3 allocations per call** — `bits_of` and the
   shared-bits scan routed through `slots()`, whose scratch
   `Vec::with_capacity(40)` allocates. Report 08's "no alloc" claim was
   never true. Fix: one `for_each_present_slot!` presence source;
   `bits_of` walks it without collecting; `diff` walks the shared bits
   directly. The unchanged path is now EXACTLY zero — and
   `diff_unchanged` dropped 238.8 → 139.8 ns (report 08).
2. **The warm cache hit allocates ZERO** — `PlanCache::resolve` returns
   an `Arc<CachedPlan>`; the "plan clone" is a refcount bump. The
   contract was corrected to the STRONGER claim (exact zero).

After the fix:

```
$ cargo test -p aeolus-core --test alloc_contract
test cached_hit_allocates_nothing ... ok
test cn_and_cold_resolve_are_counted ... ok
test diff_of_equal_plans_allocates_zero ... ok
test intern_hit_allocates_nothing ... ok
```

Stability: 5/5 consecutive runs green (the measured sections take the
minimum of three runs — harness bookkeeping can allocate inside a
window, noise only adds).
