# 21 — The xtask generator story and the attribute-probe interp surface

Two slices shipped in one handoff, one red→green cycle per milestone:

* **M1** — the xtask generator story (plan §3.2's row for `aeolus-data`,
  the LAST named P2 slice: "Generated by `xtask` into committed Rust
  (phf/trie). Also generates: docs, linter tables, class-sort order,
  test fixtures"): the `codegen::GeneratedArtifact` seam, the generated
  roots index wired into the registry read side (the pre-index linear
  scan stays as the documented `lookup_linear` oracle), the committed
  `docs/REGISTRY.md` audit page, and the `crates/xtask` driver
  (`gen-tables`/`verify-tables`/`list` + the `cargo xtask` alias). The
  linter tables / class-sort order / fixture-corpus artifacts stay
  DOCUMENTED as the seam's growth path — the read side's typed miss and
  the existing corpus pins cover their jobs today; none is half-built.
* **M2** — the attribute-probe interp surface (plan §3.5's answer, the
  follow-up the `InterpNote::AttributeUnqueried` note has named since
  the fold landed): the `AttrProbe` seam (one question — what value does
  the element carry for this attribute?), the built-in `AttrState`
  static-bit table, and the `interp_probes`/`interp_theme_probes` entry
  points (the `compile_with` convention). A probe layer FIRES when the
  element carries the attribute (presence) or the folded value
  (equality); a source-answered miss is CSS-quiet (a selector that does
  not match, not an exclusion); the `has-`/`group-has-`/`peer-has-`
  descendant probes stay the plan §3.5 row's diagnosed boundary —
  reported, honest failure kept — because the descendant shape is not
  an attribute bit.

The M1 differential oracle is IN the crate: `registry::lookup_linear`
is byte-for-byte the pre-index scan, and `tests/codegen.rs` batteries
the two over every root (exact, `-4`, `-red`), the multi-dash
composites, the adversarial misses and a deterministic 4000-body
pseudo-random fuzz — the lookup semantics cannot drift with the fast
path, and the committed bytes are pinned equal to the regeneration so a
row edit that forgets `cargo xtask gen-tables` fails `cargo test`.

**GREEN (the seam, the generated index, the wiring — every pin satisfied):**

```text

test result: ok. 12 passed  (tests/registry.rs — the P1 pins, unchanged)
$ cargo test -p xtask

                             the temp-root write/verify cycle, the live

$ cargo test --workspace --all-features          # 0 failures
```

What the battery pins (`crates/aeolus-data/tests/codegen.rs`):

1. **The seam** — `codegen::artifacts()` lists exactly
   `roots-index` → `crates/aeolus-data/src/roots_index.rs` and
   `registry-docs` → `docs/REGISTRY.md`, workspace-relative paths.
2. **The drift pins** — the committed bytes of BOTH artifacts equal
   the regeneration (`include_str!` for the index; the manifest-relative
   read for the docs page) — the one-source-of-truth claim, enforced.
3. **Determinism** — two renders byte-identical per artifact.
4. **The index invariants** — the generated entries PARTITION the rows
   (every row indexed exactly once under its own root), every distinct
   root is indexed exactly once, every entry is reachable within the
   emitted `PROBE_BOUND`, and the slot table is a power-of-two at most
   half full.
5. **The differential battery** — `lookup` (indexed) answers exactly
   what `lookup_linear` (the oracle) answers, root-for-root and
   row-for-row, over the roots, the composites, the adversarial bodies
   and the deterministic fuzz; the typed misses carry the same MODE
   (`UnknownRoot` iff no registered root dash-matches the body;
   `ShapeRejected` for the oracle's own winning root, with the tried
   labels).
6. **The read-side contract** — the rows the index path hands back
   carry the same fields the compile stage's value pass keys on.

The generated module (`src/roots_index.rs`, 512 slots, seed 0, probe
bound 4 — one seed placed every root with maximum displacement 3):
the seeded-FNV hash embedded verbatim so generation and runtime agree
by construction, the slot table and entries (`#[rustfmt::skip]`, one
slot per line — byte-stable under `cargo fmt`), the longest-prefix
probe (dash-aligned prefixes longest-first — the registry's own
`body_matches_root` rule read backwards), and the empty-slot
terminator. The `docs/REGISTRY.md` page is `registry::generate_docs`'s
render — one source of truth for the rendering too.

## M2 — the attribute-probe interp surface

**RED→GREEN (same handoff, second milestone):**

```text
$ cargo test -p aeolus-compile --test probes
error[E0432]: unresolved imports `aeolus_compile::AttrBit`, `AttrKind`,
              `AttrState`, `interp_probes`, `interp_theme_probes`
error[E0599]: no method named `interp_probes` found for struct `Compiled`

$ cargo test -p aeolus-compile --test probes
test result: ok. 13 passed
```

What the battery pins (`crates/aeolus-compile/tests/probes.rs`):

1. **The firing semantics** — `data-[state=open]:p-8` fires under the
   element's `("state", "open")` bit; the bare presence spelling
   (`data-slot:`) fires on ANY value of the attribute; the aria bare
   spelling (the `"true"` normalization the fold pins) fires only on
   the exact value.
2. **The quiet-miss rule** — a value mismatch and an absent attribute
   both leave the layer OUT with ZERO notes: the probe was ANSWERED,
   and a CSS selector that does not match is CSS-quiet (the
   no-silent-failures rule governs unqueried exclusions, not answered
   misses).
3. **The back-compat boundary** — the plain `interp` keeps the
   `AttributeUnqueried` notes (unchanged behavior, the sourceless
   entry points carry no seam), and the descendant probes
   (`has-focus:`, `group-has-[:focus]:`, `peer-has-data-[…]:`) stay
   reported even WITH a source — the plan §3.5 diagnosed boundary.
4. **The cascade** — a fired probe layer wins per longhand over the
   base (`p-4 data-[state=open]:p-8` → all four paddings at the probe
   layer's value); an unfired probe layer leaves the base's value.
5. **The themed combo** — `interp_theme_probes` rides BOTH seams in
   one walk: `bg-primary` resolves through the `TokenSource` while the
   probe layer fires through the `AttrProbe`.
6. **The custom-seam composition** — a registered `CustomVariant`
   alias onto a probe `Cond` folds and FIRES through the same surface
   (the seams compose, no special cases).
7. **The ergonomic half + purity** — `Compiled::interp_probes` and the
   deterministic same-input-same-answer pin.

## Honest boundaries surfaced (all documented in the module docs)

* the linter tables, the class-sort order and the fixture-corpus
  artifacts stay UNBUILT (documented on the seam as its growth path —
  the typed miss and the corpus pins cover their jobs today); the
  driver's artifact list is where they join;
* the index answers WHICH ROOT a body addresses — the per-row shape
  contract stays in `registry.rs`, and the linear scan stays public as
  the differential oracle (the bench's before-number side);
* the interpreter's probe seam answers the element-OWN attribute
  probes only — the descendant shapes (`has-`/`group-has-`/
  `peer-has-`) stay the reported diagnosed boundary with or without a
  source (the plan §3.5 row's own verdict), and the named group/peer
  label still has no IR slot;
* a source-answered probe miss is CSS-quiet by DESIGN (the note is for
  unqueried exclusions) — the docs pin the distinction so the
  no-silent-failures rule stays about honesty, not noise;
* the generated module is `#[rustfmt::skip]`-guarded where its layout
  is data (one slot per line), and the drift pins compare RAW bytes —
  `cargo fmt` cannot silently reorder the index.
